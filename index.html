Student Performance & Attendance

A Bronze → Silver → Gold pipeline built in Databricks and staged into Snowflake, tracing exactly how attendance drives academic outcomes across 1,200 students, three semesters, and six subjects.

1Pipeline

Five stages, chained as dependent tasks in a scheduled Databricks Job, running unattended from raw generation through to a Snowflake-ready export.

  • 01

    Generate

    Seeded synthetic dataset — 1,200 students × 3 semesters × 6 subjects, with defects injected for the pipeline to catch.

  • 02

    Bronze land, don't clean

    Raw CSVs read as-is, every column a string, provenance columns added. Nothing altered.

  • 03

    Silver decide & log

    try_cast, dedupe on the natural key, reject orphans and out-of-range rows with a named reason, derive attendance bands and semester ranks.

  • 04

    Gold

    One row per student × semester × subject, joined against student and subject dimensions — the shape that travels.

  • 05

    Export

    Coalesced to a single CSV, staged in Snowflake, loaded with COPY INTO — idempotency verified by re-running the same load.

3Silver decisions

Four judgement calls, each logged rather than silently applied.

try_cast, never cast — 'AB' becomes 0

300 rows held the literal string 'AB' in internal_marks — a genuinely absent assessment, not a zero score. try_cast turns it into NULL; coalesce(..., 0) makes it computable without hiding the absence.

assert count = 300 → passed

Dedupe on (student_id, semester, subject_code)

Keyed on the natural business key, not the whole row — a resent record can carry an identical row with only a different ingestion timestamp.

480 rows removed

Orphans and range rejects, named

unknown_student (anti-join), attendance_over_100, no_classes_held, marks_over_max — four named reasons, all preserved in silver_rejects rather than discarded.

560 rows rejected, with reason

Attendance band, completeness, and rank

Bands derived from the unrounded percentage to avoid boundary misclassification. Rank computed only over students complete across all 6 subjects in a semester, so an incomplete record can't distort it.

905 students complete in both sem 1 & 2

4Idempotency proof

The load into Snowflake was run twice against the same staged file.

› COPY INTO GOLD_STUDENT_SUBJECT_SEM FROM @gold_stage ...
✓ 21,160 rows loaded
SELECT COUNT(*) FROM GOLD_STUDENT_SUBJECT_SEM;
→ 21160

› COPY INTO GOLD_STUDENT_SUBJECT_SEM FROM @gold_stage ... (run again, same file)
✓ Copy executed with 0 files processed.

Snowflake's load metadata recognized the file had already been loaded and correctly skipped it — the load is safe to re-run without duplicating data.
